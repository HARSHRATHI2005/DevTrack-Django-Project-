# DevTrack – Engineering Issue Tracking API

## 1. Project Overview

DevTrack is a backend API developed using Django and Django REST Framework. It helps engineering teams report bugs, assign priorities, and track issue statuses.

The project demonstrates Object-Oriented Programming (OOP), inheritance, method overriding, data validation, URL routing, and API testing using Postman.

## 4. Data Models and OOP Design

### BaseEntity

An abstract base class that defines the `validate()` method and provides a reusable `to_dict()` method.

### Reporter

Represents a person who reports an issue.

Attributes:
- `id`
- `name`
- `email`
- `team`

Validation ensures that the name and team are not empty and that the email contains `@`.

### Issue

Represents a bug report or task.

Attributes:
- `id`
- `title`
- `description`
- `status`
- `priority`
- `reporter_id`
- `created_at`

Allowed statuses:
- `open`
- `in_progress`
- `resolved`
- `closed`

Allowed priorities:
- `low`
- `medium`
- `high`
- `critical`

### Inheritance and Method Overriding

`Reporter` and `Issue` inherit from `BaseEntity`.

Two subclasses inherit from `Issue`:

- `CriticalIssue`: Overrides `describe()` to display an urgent message.
- `LowPriorityIssue`: Overrides `describe()` to display a low-priority message.

For medium and high priorities, the base `Issue` class is used.

## 5. API Endpoints

Base URL: `http://127.0.0.1:8000`

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/reporters/` | Create a reporter |
| GET | `/api/reporters/` | Retrieve all reporters |
| GET | `/api/reporters/?id=1` | Retrieve a reporter by ID |
| POST | `/api/issues/` | Create an issue |
| GET | `/api/issues/` | Retrieve all issues |
| GET | `/api/issues/?id=1` | Retrieve an issue by ID |
| GET | `/api/issues/?status=open` | Filter issues by status |

## 6. Sample API Requests

### Create a Reporter

**Method:** POST

**Endpoint:** `/api/reporters/`

Request body:

```json
{
  "name": "Rahul Sharma",
  "email": "rahul@example.com",
  "team": "backend"
}
```

Expected status: `201 Created`

### Create an Issue

**Method:** POST

**Endpoint:** `/api/issues/`

Request body:

```json
{
  "title": "Login button not working on mobile",
  "description": "Users on iOS 17 cannot tap the login button",
  "status": "open",
  "priority": "critical",
  "reporter_id": 1
}
```

Expected status: `201 Created`

The response includes a message generated by the appropriate `describe()` method.

## 7. Validation and Error Handling

The API validates reporter and issue data before saving it.

- `201 Created`: Record created successfully.
- `200 OK`: Request completed successfully.
- `400 Bad Request`: Invalid input or validation failure.
- `404 Not Found`: Requested record does not exist.

Examples of validation failures include an empty issue title, an invalid email, an unsupported priority, or an unsupported status.

## 8. Data Storage

The project stores records in JSON files:

- `issues/files/reporters.json`
- `issues/files/issues.json`

The `reporter_id` field in an issue links it to the reporter who created it. One reporter can have multiple issues.

JSON storage was selected to satisfy the assignment requirements without configuring a database for the issue records.

## 9. How to Run the Project

### Step 1: Clone the repository

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
cd devtrack
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with your actual public repository URL.

### Step 2: Create a virtual environment

```bash
python -m venv venv
```

### Step 3: Activate the virtual environment

On Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks script execution, run the following in the same terminal and activate the environment again:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

### Step 4: Install dependencies

```bash
pip install django djangorestframework
```

### Step 5: Run the development server

```bash
python manage.py runserver
```

The API will be available at:

`http://127.0.0.1:8000/`

## 11. Design Decision

I used an abstract `BaseEntity` class to provide a common validation contract and a reusable `to_dict()` method for both Reporter and Issue.

I also used inheritance and method overriding for critical and low-priority issues so that each priority type can return a different description without duplicating the main issue implementation.

JSON files were used for storage because the assignment focuses on OOP concepts, Django API development, and request handling.
